# Архитектура KVM

## Общая схема

Стек виртуализации KVM можно представить следующим образом:

```text
               Пользователь
                    │
          virsh / virt-manager
                    │
                 libvirt
                    │
             qemu-system-x86_64
                    │
      ┌─────────────┴───────────────┐
      │         Ядро Linux          │
      │                             │
Виртуальные устройства         KVM (модуль ядра)
(диски, сеть, BIOS, GPU)            │
      │                             │
      └─────────────┬───────────────┘
                    │
           Intel VT-x / AMD-V
                    │
          Физическое оборудование
```

---

# Как работает стек KVM

## 1. Физическое оборудование

Основа всей системы - **хост-машина** (сервер или ПК), на которой запускаются виртуальные машины.

Она включает:

- процессор;
- оперативную память;
- накопители;
- сетевые устройства;
- остальные аппаратные компоненты.

---

## 2. Аппаратная виртуализация (Intel VT-x / AMD-V)

Современные процессоры поддерживают аппаратную виртуализацию:

- **Intel VT-x** - процессоры Intel;
- **AMD-V** - процессоры AMD.

Эти технологии позволяют выполнять код гостевой операционной системы практически напрямую на процессоре без полной программной эмуляции, что значительно увеличивает производительность.

---

## 3. Ядро Linux

Ядро Linux управляет аппаратными ресурсами компьютера:

- памятью;
- процессором;
- устройствами ввода-вывода;
- файловыми системами;
- сетью.

Именно в ядре находится модуль **KVM**.

---

## 4. KVM (Kernel-based Virtual Machine)

**KVM** - это модуль ядра Linux, который превращает Linux в гипервизор первого типа (Type 1).

Основные задачи KVM:

- создание виртуальных процессоров (vCPU);
- управление памятью виртуальной машины;
- использование аппаратной виртуализации Intel VT-x или AMD-V;
- выполнение инструкций гостевой ОС непосредственно на процессоре.

> **Важно:** KVM сам по себе не создает виртуальный компьютер. Он отвечает только за виртуализацию процессора и памяти.

---

## 5. QEMU

**QEMU (Quick Emulator)** - программа, которая создает виртуальный компьютер.

QEMU эмулирует виртуальное оборудование:

- жесткие диски;
- сетевые карты;
- BIOS/UEFI;
- USB-устройства;
- видеокарты;
- контроллеры хранения данных;
- другие виртуальные устройства.

После создания виртуального оборудования QEMU передает выполнение кода гостевой ОС модулю KVM, который обеспечивает аппаратное выполнение инструкций процессора.

> **KVM отвечает за выполнение кода, а QEMU - за виртуальное оборудование.**

---

## 6. Storage

Диски виртуальных машин обычно представлены файлами на файловой системе хоста.

Наиболее распространенные форматы:

- **qcow2** - поддерживает снапшоты, сжатие и тонкое выделение места;
- **raw** - простой образ диска без дополнительных возможностей, но с максимальной производительностью.

---

## 7. libvirt

**libvirt** — слой управления виртуализацией.

Он предоставляет единый API для работы с различными гипервизорами (KVM, QEMU, Xen и другими) и скрывает детали взаимодействия с ними.

Основные возможности:

- создание виртуальных машин;
- запуск и остановка;
- управление сетью;
- управление хранилищами;
- настройка виртуального оборудования;
- хранение конфигурации ВМ (XML).

Без libvirt администратору пришлось бы вручную запускать QEMU с большим количеством параметров командной строки.

---

# Архитектура libvirt в современных Ubuntu

Начиная примерно с **Ubuntu 22.04**, архитектура libvirt изменилась.

Раньше практически вся функциональность находилась в одном процессе **libvirtd**.

```text
libvirtd
├── QEMU
├── сеть
├── хранилища
└── устройства
```

Теперь используются отдельные специализированные службы:

- **virtqemud** - управление QEMU;
- **virtnetworkd** - управление виртуальными сетями;
- **virtstoraged** - управление хранилищами;
- **virtnodedevd** - управление оборудованием хоста.

Новая архитектура:

```text
virtqemud
virtnetworkd
virtstoraged
virtnodedevd
```

### Преимущества

- проще сопровождать код;
- проще обновлять отдельные компоненты;
- выше отказоустойчивость;
- отказ одного сервиса не приводит к остановке остальных.

Например, если возникнет проблема с сервисом управления сетью, уже работающие виртуальные машины продолжат функционировать.

# virsh

**virsh (Virtual Shell)** - консольная утилита для управления виртуальными машинами через **libvirt**.

Важно понимать, что **virsh не работает с QEMU напрямую**. Все команды передаются через libvirt.

Схема взаимодействия:

```text
virsh
   │
   ▼
libvirt
   │
   ▼
QEMU + KVM
```

---

# Основные команды virsh

| Команда | Назначение |
|----------|------------|
| `virsh list --all` | Показать все виртуальные машины |
| `virsh start <vm>` | Запустить ВМ |
| `virsh shutdown <vm>` | Корректно выключить ВМ |
| `virsh destroy <vm>` | Принудительно выключить ВМ |
| `virsh reboot <vm>` | Перезагрузить ВМ |
| `virsh suspend <vm>` | Приостановить работу ВМ |
| `virsh resume <vm>` | Возобновить работу ВМ |
| `virsh dumpxml <vm>` | Показать XML-конфигурацию |
| `virsh edit <vm>` | Изменить XML-конфигурацию |
| `virsh dominfo <vm>` | Информация о ВМ |
| `virsh dommemstat <vm>` | Статистика использования памяти |
| `virsh cpu-stats <vm>` | Статистика использования процессора |
| `virsh autostart <vm>` | Включить автозапуск |
| `virsh undefine <vm>` | Удалить конфигурацию ВМ (без удаления дисков) |
| `virsh console <vm>` | Подключиться к консоли виртуальной машины |

---

# Краткое распределение ролей

| Компонент | Назначение |
|-----------|------------|
| **Физическое оборудование** | Предоставляет вычислительные ресурсы |
| **Intel VT-x / AMD-V** | Аппаратная поддержка виртуализации |
| **Ядро Linux** | Управляет аппаратными ресурсами |
| **KVM** | Выполняет код гостевой ОС с помощью аппаратной виртуализации |
| **QEMU** | Создает виртуальный компьютер и виртуальные устройства |
| **Storage** | Хранит диски виртуальных машин |
| **libvirt** | Управляет жизненным циклом виртуальных машин |
| **virsh** | Консольный инструмент администратора |
| **virt-manager** | Графический интерфейс управления |

---

## Итог

Весь стек KVM можно представить следующим образом:

```text
Пользователь
    │
virsh / virt-manager
     │
  libvirt
     │
   QEMU
     │
    KVM
     │
Intel VT-x / AMD-V
     │
Физическое оборудование
```

- **KVM** - виртуализирует процессор и память.
- **QEMU** - создает виртуальный компьютер и устройства.
- **libvirt** - управляет виртуальными машинами.
- **virsh** - консольный интерфейс управления.
- **virt-manager** - графический интерфейс управления.
